## Playback

`useSecurityScenario` owns one finite Motion value for each demonstration.
Explicit checkpoints drive React state; SVG motion derives from that same clock.
The orbital system progresses through initialization, domains, scanning,
partial results, correlation, risk, recommendations, correction and protection.
Visibility and document lifecycle
pause the clock, preserving progress. Visible scenarios run one at a time;
manual play or a demo action gets priority. Pause, replay and the nine stage
controls remain available. Reduced motion renders the completed state and keeps
all demo controls usable. The local controls never start a real audit or change
an external system.

V19 uses the shared `useIdleReplay` controller: the shield rests for 8 seconds
and application demos for 12 seconds before requesting another turn. Activity
extends the deadline to 30 seconds after the latest event. Pointer holds and
editable focus prevent reset; explicit Pause and the surveillance-off switch
remain paused. Offscreen/background time does not consume the return grace
period. Each eligible demo owns one cancellable timeout; reduced motion never
automatically replays. Replay invokes the demo's existing state-reset callback.

The four marketing blocks deliberately vary their compositions: audit header
above a broad application, findings interface left and editorial right,
centered correction with an inset progress card, and a full-width monitoring
chart. Mobile stacks these elements without changing their functional controls.
The orbit uses stronger gold/green paths and red detection, orange correction,
then green verification, including the affected domain and its signal.

The four interfaces support scope switches and analysis tabs, a severity filter
and inline finding detail, correction checkboxes and a journal, and a monitoring
period selector and surveillance switch. Data, systems, dates, findings and risk
indices are fictional deterministic examples, not customer audit results.

forest-green wall, pale stone columns, carved ceiling, lateral windows and

`assets/security-team-v18.png` is an Imagegen edit of the existing UV atlas:

source-size generated artwork, not upscaled screen captures.

For the encoded team WebP, the original atlas alpha and small rigged eye islands
are restored exactly. The edit is resized to the original atlas's 2048×2048
technical texture size and vertically encoded to match the existing GLB UVs.
This is texture conditioning, not a UI image sequence.
`scripts/build-bump-security-models.mjs` appends that atlas to a new foreground
GLB without replacing its compressed geometry, skeleton, bones or animation
buffers. `assets/model-report.json` records their hash and retained tracks.
The table globe GLB remains byte-for-byte unchanged. The new opaque room follows
and covers the native camera; portrait FOV and camera framing keep the group
in view. V19 retires five separate eyelid overlay meshes that were registered to
the former faces, while retaining their transform nodes, the original binary
geometry, skeleton and animation tracks. Bump's painted faces underneath remain
complete; the old eyelid blink patches no longer render. The hero retains its
native 140svh interval, with title and three short introduction lines contained
inside the first 88svh. The separate IA paper wipe starts 0.3 viewport units
earlier and finishes higher, so its first content title is fully on paper.

Non-WebGL posters are actual rendered frames of this same scene. Browsers with
WebGL use the original animated meshes and globe, not a flattened poster.
